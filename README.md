# Car search

[![CI](https://github.com/GeneralFire/cn_search/actions/workflows/ci.yml/badge.svg?branch=master)](https://github.com/GeneralFire/cn_search/actions/workflows/ci.yml)

Look up where and when a car was seen (its *sightings*) by its licence plate. The stack is a Go backend
(the contract lives in proto, HTTP handlers are generated by [clay](https://github.com/utrack/clay)),
Postgres, S3 storage for photos, and a TypeScript + Vite frontend that uses a TS client generated from
`swagger.json`.

> **Pet project.** Dependencies come only from public registries
> (npmjs.org, proxy.golang.org, Docker Hub). See
> [Dependencies and environment](#dependencies-and-environment) and `CLAUDE.md` for details.

Docs:
- **[docs/DATA_SOURCES.md](docs/DATA_SOURCES.md)** — where real sighting data (photo + time + place) could come
  from, and the legal side of it;
- **[docs/OCR_PIPELINE.md](docs/OCR_PIPELINE.md)** — photo → OCR → sighting (`Ingest`, the `ocr` service, models,
  accuracy, privacy TODOs);
- **[docs/IDEAS.md](docs/IDEAS.md)** — 100 product ideas with a top-10 in parallel waves.

## Quick start

You need Docker (Docker Desktop / Colima / OrbStack), Docker Compose and `make`.

```bash
make run    # start everything: db + s3 (+ migrations with test data and photos), be, fe
```

Or piece by piece:

```bash
make etc      # DB and S3 only: goose migrations (with test data) + bucket with photos
make run-be   # backend only (rebuilds it); needs make etc
make run-fe   # frontend only; without the backend the page opens but search fails
make stop-fe  # / stop-be / stop-etc — stop one part; make down — everything
```

Open **http://localhost:7173** (from the local network: `http://<your-IP>:7173`).

| Service | What | Address |
|---|---|---|
| `fe` | Vite dev server with hot reload | `0.0.0.0:7173` — the only port a browser needs |
| `be` | clay HTTP handlers + gRPC | `127.0.0.1:8080` (HTTP), `127.0.0.1:8082` (gRPC) |
| `db` | Postgres 17 | `127.0.0.1:5432`, database `carsearch` |
| `s3` | [RustFS](https://github.com/rustfs/rustfs), S3-compatible storage | `127.0.0.1:9000` (S3 API), `127.0.0.1:9001` (console) |
| `ocr` | plate recognition for `Ingest` (Python, [fast-alpr](https://github.com/ankandrew/fast-alpr), ONNX on CPU): `POST /recognize` | compose network only (`http://ocr:8000`), no published port |
| `migrate` | [goose](https://github.com/pressly/goose) (`kukymbr/goose-docker`): `goose up` on `make etc` / `make run`, then exits | — |
| `s3-init` | `amazon/aws-cli`: creates the `cars` bucket (anonymous read) and uploads the test photos, then exits | — |

DB and S3 data live on the host in `./.data` (bind mount, listed in `.gitignore`). They survive restarts,
`docker-compose down -v`, volume pruning and re-creating the Docker VM. Only `make reset` deletes them.

The browser talks to the frontend only: Vite proxies `/api/*` → `be` and `/s3/*` → `s3`.
So other people on your network need just one open port.

> MinIO is not used: `minio/minio` images are no longer published on Docker Hub.
> RustFS is API-compatible with it.

## API

The contract is `be/api/carsearch/carsearch.proto` (`package carsearch`), **without HTTP annotations**.
clay generates handlers with the `generate_unbound_methods` flag: each method is exposed as
`POST /<package>.<Service>/<Method>` with a JSON body; the backend mounts them under `/api`.

| Method | HTTP | |
|---|---|---|
| `Search` | `POST /api/carsearch.CarSearchService/Search` | search plates (one card per plate) |
| `Get` | `POST /api/carsearch.CarSearchService/Get` | all sightings of a plate by any sighting id |
| `SeeAlso` | `POST /api/carsearch.CarSearchService/SeeAlso` | recent sightings of other plates (plate page) |
| `Clarify` | `POST /api/carsearch.CarSearchService/Clarify` | suggest the correct plate for a sighting |
| `Complain` | `POST /api/carsearch.CarSearchService/Complain` | report a sighting photo |

| `ListClarifications` / `SetClarificationStatus` | `POST /api/carsearch.CarSearchService/…` | admin: list clarifications, accept/reject one manually |
| `HideSighting` | `POST /api/carsearch.CarSearchService/HideSighting` | admin: hide a sighting from users (or show it again) |

### Search

```jsonc
// request — every field is optional
{ "plate": "А123ВС 777", "offset": 0, "limit": 35, "market": "" }

// response
{
  "items": [{ "id": "00000000-0000-0000-0000-000000000004", "photoUrl": "/s3/cars/car-9.jpg",
              "thumbUrl": "/s3/cars/car-9_thumb.jpg", "address": "Москва, ул. Тверская, 7",
              "addressLocale": "ru", "plate": "А123ВС 777", "plateType": "PLATE_TYPE_RU",
              "lat": 55.7579, "lon": 37.6115, "createdAt": "2026-11-05T18:30:00Z" }],
  "total": 1,          // total number of plates found — always present, including 0
  "nextOffset": 35,    // offset of the next page; absent — nothing more
  "suggestions": []    // "did you mean": only when total = 0 for a non-empty query
}
```

- **One plate — one card**: the latest matching sighting of each plate. Newest first (`createdAt`).
- Search **by word prefixes of the plate** (`to_tsvector('simple', …) @@ to_tsquery(…)`, GIN index):
  `У54` → `У543РУ 152`, `А123ВС 77` → `А123ВС 777`, `77` → every plate with region 77.
  The query string is parsed in SQL: words are split on spaces, only letters and digits are kept,
  each word becomes a prefix (`:*`), all joined with AND: `А12 77` → `'А12':* & '77':*`. Case-insensitive.
- **Look-alike characters do not matter**: the SQL function `plate_search_key` (migration 0001) maps
  Cyrillic plate letters to their Latin twins, the letter O to the digit 0, hyphen and `·` to a space, and
  Ukrainian `І` to Latin `I`. It is applied the same way to the plate in the GIN index and to the query:
  `0515`, `O515HX`, `о515нх` all find `О515НХ 52`; `kdt 44` finds `KDT-4419`. A repository test checks that
  the index expression and the query match; `fe/src/searchkey.ts` is a JS copy used to highlight the match
  (`node fe/scripts/searchkey-check.ts` compares it with the migration).
- Does not match the middle of a word (`543`) or a plate glued to its region (`У543РУ152`). Empty — all plates.
- **Did you mean**: when a non-empty query finds nothing, `suggestions` holds up to 5 plates (latest sighting
  each) within Levenshtein distance ≤ 2 of the query, compared by `plate_search_key` without spaces
  (`levenshtein` from the `fuzzystrmatch` contrib extension, created by migration 0001), closest first.
- Clarifications of a sighting (accepted or not) are searched along with its plate.
- **Mask search** (`"mask": true`): `plate` is a mask where `*` stands for exactly one arbitrary character, matched
  against the whole plate without spaces (`А*23ВС 77*` and `a*23bc77*` both find `А123ВС 777`). Only letters, digits,
  spaces and `*` are kept (the rest is dropped; `%` and `_` are not wildcards); fewer than 3 known characters
  (not `*`) is `InvalidArgument`. The pattern goes through `plate_search_key` in SQL, so look-alike characters
  and case do not matter. It replaces the word-prefix search (no `suggestions`); filters, test data, hidden
  sightings, one card per plate, `total` and paging work as usual.
  **Performance:** the mask is a `LIKE` over every plate — it cannot use the GIN index, so it is a full scan of
  the plates (fine for the demo data, linear in the number of plates). `pg_trgm` is deliberately not used.
  In the UI it is the `*` "Mask" toggle next to the search field (`?mask=1` in the address).
- `limit`: 1–100, `0` means the default 35 (a multiple of 5 and 7 — grid column counts).
- `market` — plate "market" for the home page, by plate format in `plates.meta` (`type`, `region`):
  `ru`, `ua`, `de` (EU with region `D`), `us`, `cn`, and `other` — everything not in any of those. Empty — no filter.
- An `items` element is a `PlateSighting`. `lat`/`lon` (WGS 84) are optional — absent when the point is unknown.
- Sightings hidden by an admin (`HideSighting`) are not returned to users in `Search`/`Get`/`SeeAlso`; with a valid
  `admin-token` they are returned with `hidden: true`.
- The **`include-test-data`** header (any value except `false`/`0`) includes rows with
  `is_test_data = true`. Without it test data is never returned. Works for `Search`, `Get`, `SeeAlso`
  and over gRPC (metadata).

### Get

By the id of any sighting — **all sightings of the same plate**, newest first:

```jsonc
// request
{ "id": "00000000-0000-0000-0000-000000000001" }

// response
{ "items": [
  { "id": "…0004", "address": "Москва, ул. Тверская, 7",     "plate": "А123ВС 777", "createdAt": "2026-11-05T18:30:00Z", … },
  { "id": "…0001", "address": "Москва, Пресненская наб., 10", "plate": "А123ВС 777", "createdAt": "2026-11-02T09:15:00Z", … },
  { "id": "…0005", "address": "Москва, Кутузовский пр., 30",  "plate": "А123ВС 777", "createdAt": "2026-10-20T08:00:00Z", … }
] }
```

The response also has `clarifications` — clarifications of all sightings of the plate grouped by the
suggested plate (ignoring look-alikes): plate, type/region, `count`, `status` (`ACCEPTED` if any is accepted),
`sightingIds` and the clarifications themselves; accepted first, then by count and recency. The plate page shows
them as a strip under the header ("Maybe it is А123ВС 77 · 3 suggestions · accepted") and marks sightings in the timeline.

Every `Get` is written to the `plate_views` log. With an **API token** (`cst_…`, see
[API tokens](#api-tokens)) it consumes one request: exhausted — `ResourceExhausted`, revoked —
`PermissionDenied`, bad signature — `Unauthenticated`. With `admin-token` no quota is consumed.

### SeeAlso

Recent sightings of other plates for the block at the bottom of the plate page: one card per plate, the
plate of the given sighting is excluded. `{ "id": "<sighting uuid>", "limit": 21 }` — `limit` 1–21, `0` → 21.

### Clarify

Suggest the correct plate for a sighting ("the plate is actually this one", the **Clarify** modal):

```jsonc
// request; plateType: PLATE_TYPE_RU | _EU | _US | _UA | _CN | PLATE_TYPE_DEFAULT (unknown)
{ "sightingId": "00000000-0000-0000-0000-000000000001", "plate": "x001xx99", "plateType": "PLATE_TYPE_RU" }

// response: the plate is normalized, the status is current
{ "clarification": { "id": "…", "sightingId": "…0001", "plate": "Х001ХХ 99",
                     "status": "CLARIFICATION_STATUS_NOT_ACCEPTED", "plateType": "PLATE_TYPE_RU", … } }
```

- **Normalization** (usecase): leading/trailing spaces are trimmed, inner ones collapsed, upper case.
  For RU additionally Latin twins → Cyrillic (`A B E K M H O P C T Y X`), `0` in letter positions → `О`,
  a space is inserted before the region: `x001xx99` → `Х001ХХ 99`, `0123вс 77` → `О123ВС 77`.
- **Format** by `plateType`: RU — `^[АВЕКМНОРСТУХ]\d{3}[АВЕКМНОРСТУХ]{2} \d{2,3}$`; EU/US — lenient:
  2–12 characters, Latin letters, digits, space, hyphen (`plateRegion` — up to 3 Latin letters);
  UA/CN/unknown — not checked. A wrong format is `InvalidArgument` with a user-facing message (the frontend
  shows `message` as is; messages are in Russian).
- A clarification equal to the sighting's current plate (by `plate_search_key`, i.e. ignoring look-alikes)
  is `InvalidArgument` "clarification matches the current plate".
- **Consensus**: a clarification is created "not accepted"; once **3** (`usecase.ClarificationConsensus`)
  clarifications of the same sighting match by `plate_search_key(plate)`, all of them become `ACCEPTED`
  in the same write transaction, and the response already says `ACCEPTED`. The sighting row is locked
  (`FOR UPDATE`) for the transaction, so concurrent clarifications do not miss each other when counting.
  Index `clarifications (sighting_id, plate_search_key(plate))`.

### Complaints, admin mode and the admin panel

`Complain` — report a sighting photo (the **Report** button on the plate page photo and on timeline thumbnails):

```jsonc
// request; reason: COMPLAINT_REASON_WRONG_PLATE | _BAD_PHOTO | _PERSONAL_DATA | _OTHER (required)
{ "sightingId": "00000000-0000-0000-0000-000000000001", "reason": "COMPLAINT_REASON_PERSONAL_DATA",
  "comment": "A pedestrian's face is visible" }   // comment: up to 500 characters, may be empty

// response — the created Complaint, status COMPLAINT_STATUS_NEW
```

`ListComplaints` (`offset`, `limit` 1–100 / `0` → 30, `status` filter; each item includes its sighting) and
`ResolveComplaint` (`{ "id": "<complaint uuid>" }`) require the **`admin-token`** header equal to the
backend's `ADMIN_TOKEN`; otherwise — `PermissionDenied`. An empty `ADMIN_TOKEN` disables the admin methods.

The admin UI is at a hidden path set by **`VITE_ADMIN_PATH`** (compose sets it from `ADMIN_PATH`; default in dev —
`/ops-7f3a2c`; without the variable — `/admin`). There is no link in the interface — open it directly. Any other
address, `/admin` included when the path differs, shows the 404 page. It asks for the token and
keeps it in `sessionStorage` of the tab only. Tabs (a registry in `fe/src/admintabs.ts`, active tab in `?tab=`):
**Complaints** (status filter, **Load more**, **Resolved**), **Clarifications** (pending by default,
**Accept / Reject** → `SetClarificationStatus`), **Camera requests** (with the author's contact, status change),
**Tokens** and **Views** (see [API tokens](#api-tokens)). In docker-compose the token defaults to
`carsearch-admin-dev` (local development only — set `ADMIN_TOKEN` in `.env` otherwise).

**Admin mode** (`fe/src/adminmode.ts`): once a token is stored, every API request carries `admin-token` and `Me`
confirms it (`isAdmin` → class `is-admin` on `<html>`; a wrong token is erased). Then hidden panels appear across
the UI (`fe/src/adminpanels.ts`): on the plate page a **Manage** card — hide/show each sighting (`HideSighting`),
its complaints, clarifications of the opened sighting with Accept/Reject; on the home page an **Admin** strip with
counters of new complaints and pending clarifications. Without the token there are no admin elements in the DOM.

### Ingest (photo upload with OCR)

The `/upload` page (drag & drop, file picker or the phone camera) → `Ingest`; details —
[docs/OCR_PIPELINE.md](docs/OCR_PIPELINE.md).

```jsonc
// request; photo — JPEG/PNG up to 8 MB, base64 over HTTP
{ "photo": "<base64>", "takenAt": "2026-11-12T08:30:00Z", "lat": 55.75, "lon": 37.61, "address": "Москва, ул. Тверская, 7" }

// response: the created sighting, all candidates (best first), uploads left (Free)
{ "sighting": { "id": "…", "plate": "Р466УК 79", … },
  "candidates": [{ "plate": "Р466УК 79", "raw": "P466YK79", "confidence": 0.94, "plateType": "PLATE_TYPE_RU", "bbox": [1295, 662, 1485, 750] }],
  "uploadsLeft": 4 }
```

- **Sign-in required** (user token `cs_…`; anonymous — `Unauthenticated`). Free plan — at most **5 uploads per
  rolling 24 h** (counted by `plate_sightings.uploaded_by` / `uploaded_at`), over the limit — `ResourceExhausted`;
  Pro — unlimited. Checked before OCR and again in the write transaction with the user row locked.
  `Me` and the response return `uploadsLeft`.
- Time and place: request fields win, otherwise EXIF `DateTimeOriginal` and GPS; time defaults to now, a future
  time is clamped. EXIF `Orientation` is applied.
- The `ocr` service (fast-alpr: YOLOv9 plate detector + CCT OCR, ONNX on CPU) returns candidates; each is
  normalized by format (RU Latin twins → Cyrillic, US/EU heuristics); the best one above confidence 0.5 is used,
  otherwise `InvalidArgument` "plate not recognized". OCR down — `Unavailable`.
- Photos are re-encoded (≤ 1600 px + 480 px thumbnail, **no EXIF**) into S3 `cars/u/<uuid>.jpg`; plate
  (find-or-create) and sighting are written in one transaction and are searchable immediately.
- `Ingest` is enabled only when `OCR_URL` and `S3_ENDPOINT` are set (docker-compose sets them).
- Not done yet: face / other-plate blurring, retention policy — see the Privacy section of OCR_PIPELINE.md
  and [docs/DATA_SOURCES.md](docs/DATA_SOURCES.md#7-legal-side).

### Camera requests

The `/cameras` page: a map (OpenStreetMap + Leaflet, lazy) with camera placement requests coloured by status
(`NEW`, `APPROVED`, `REJECTED`, `INSTALLED`) and a list below with a **+1** vote (once per request per browser —
`localStorage`). **Suggest a place** lets you click the map (draggable marker) or use **My location**
(geolocation), then a form: reason (1–1000 characters), optional address (≤ 300) and contact (≤ 200).
`ListCameraRequests` takes a map `bbox`, a status filter and paging (`limit` 1–500, default 100); it is public but
never returns `contact` — only with a valid `admin-token`. `SetCameraRequestStatus` is admin-only.

### API tokens

Admins issue tokens for N plate page opens (`CreateApiToken`, tab **Tokens** in the admin UI):
`cst_` + base64url(`{"tid": id, "iat": unix}`) + `.` + base64url(HMAC-SHA256(payload, `TOKEN_SIGNING_KEY`))
(`be/internal/apitoken`). The plain token is shown only once; the DB (`api_tokens`) keeps only the sha256 of the
signature, the total and `requests_left`. Changing `TOKEN_SIGNING_KEY` invalidates every issued token.

A token is sent as the `cs_token` cookie (the same login field as account tokens accepts `cst_…`) or
`Authorization: Bearer cst_…`. `Get` = `usecase.ApiTokens.OpenPlate` in one write transaction: consume one request
and write a `plate_views` row. `TokenInfo` returns the balance (shown in the settings panel). The **Views** tab is
the `plate_views` log (sighting, token, consumed, admin, user agent) with a token filter; `RevokeApiToken`
makes further `Get` calls with the token fail with `PermissionDenied`.

### Errors

```json
{ "error": "rpc error: code = InvalidArgument desc = limit: от 1 до 100 (0 — по умолчанию 35)" }
```

| HTTP | gRPC code | When |
|---|---|---|
| 400 | `InvalidArgument` | bad parameters (`limit`, `offset`, `market`, non-uuid id), plate format in `Clarify`, complaint reason/comment |
| 401 | `Unauthenticated` | user token required (payments, `Ingest`, `TokenInfo`) or an API token with a bad signature |
| 403 | `PermissionDenied` | missing or wrong `admin-token`, revoked API token |
| 429 | `ResourceExhausted` | API token has no requests left, Free upload quota exhausted |
| 503 | `Unavailable` | the OCR service is unreachable (`Ingest`) |
| 404 | `NotFound` | sighting / complaint not found |
| 500 | `Internal` | server error |
| 500 | — | malformed JSON or an unknown field in the request (clay parse error) |

The marshaler and error format are clay's defaults (`runtime.JSONPb{}` and `DefaultSetError`), not customized:
zero-valued fields are omitted from responses (an empty search is `{}`), the frontend fills in defaults.

## Code generation and CI

CI (`.github/workflows/ci.yml`, push/PR to master):

- **Go**: `go vet` + `go test -race` with a Postgres service and goose migrations — integration tests of
  `repository` run via `TEST_DATABASE_URL`;
- **Frontend**: `npm ci` from npmjs, `tsc --noEmit` + `vite build` (Node 24);
- **Public registries only**: `make check-registries`;
- **Generated code is up to date**: `make ci-check` — `make gen` with protoc `PROTOC_VERSION` and the
  generator versions from the Makefile (`make tools-go`) must leave `git diff` empty.
  Changed the proto or a `contracts.go`? Run `make gen` and commit the result.

Runs on master are never cancelled (each commit gets a result); PR runs cancel superseded ones.

```
carsearch.proto ──protoc──► be/pkg/…/*.pb.go, *_grpc.pb.go      (protoc-gen-go, -go-grpc)
                └─────────► be/pkg/…/*.pb.goclay.go              (protoc-gen-goclay: HTTP handlers)
                └─────────► be/schema/carsearch.swagger.json     (clay, swagger_path)
                                   └──swagger-typescript-api──► fe/src/api/generated.ts
```

Changed the proto → `make gen` → method in `internal/implementation` → scenario in `internal/usecase` →
query in `internal/repository` → use it in `fe/src/api/index.ts` → `make test`.
You need `protoc` (`brew install protobuf`) and `make tools` once.
Generated code is committed — building does not need the generators.

clay writes a separate swagger to `<goclay_out>/<swagger_path>/<proto name>.json`. To put it into
`be/schema`, `gen-go` passes `swagger_path=../schema` and the protoc flag `--unsafe_allow_out_dir_escape`
(otherwise protoc refuses to write outside the output directory), then renames the file to `carsearch.swagger.json`.

## Frontend

- **Home page without a query** (`src/home.ts`): a **"for you"** block — the first 2 rows of plates from
  the "market" of the UI language (ru → RU plates, uk → UA, de → DE, en → US, zh → CN), then **country tabs**
  (the other markets in menu order) and **Other** (everything without a known market). The selected tab is
  in the URL (`?tab=de`, via `replaceState`): Back does not step through tabs, and returning from a plate
  page lands on the same tab.
- **Search field**: prefix search with a 250 ms debounce; stale requests are cancelled. The query is kept in
  the URL (`?q=`), so reload, history, links and switching language keep the results. Matches are highlighted
  in cards; an empty result shows **Did you mean** buttons with `suggestions`.
- **Infinite scroll**: pages of 35 load when the bottom of the list approaches the viewport
  (`IntersectionObserver`). At the bottom — a **Load more** button and "Shown N of total";
  the button also works manually and turns into **Retry** after an error.
- Grid: cards at least 400px wide, at most 7 columns; the home grid is denser (cards from 150px).
- **Clicking a card** opens the plate page `/plate/<sighting id>` (History API, no reload):
  a big plate rendered in its country's format (RU/EU/US/UA/CN/unknown), cities, "last seen … ago",
  stats (sightings, places, first, last), the latest photo (hover preview of full photos on thumbnails)
  and a timeline of all sightings (the opened one is highlighted). Back returns to the same results and
  scroll position. A search field with a dropdown (with recent queries and look-alike-aware match
  highlighting) is in the plate page header. **See also** — recent sightings of other plates.
  Direct links work (Vite serves `index.html` for any path).
- **Map** (`src/map.ts`): all sightings of the plate with coordinates on OpenStreetMap (Leaflet, loaded lazily
  only on the plate page). Markers are numbered by time (1 = earliest), a line shows the route in that order,
  the opened sighting is highlighted; clicking a marker opens that sighting, hovering a timeline item
  highlights its marker and vice versa. Hidden when no sighting has coordinates.
- **Gallery** (`src/lightbox.ts`): all photos of the plate full screen — ←/→ (buttons and keyboard), swipe,
  zoom by wheel / pinch / double click with panning, caption "address · date · 3 / 7", neighbour preloading,
  a link to the sighting. Esc closes it and returns focus.
- **Clarify** button (on home cards and on the plate page): a modal with the plate format (segments), plate,
  region (EU/US) and a preview → `Clarify` → status.
- **Upload** (`/upload`, link in the settings panel): drop a photo, pick a file or shoot with the phone camera
  (`capture=environment`); **My location** fills coordinates; files over 8 MB are shrunk in the browser (EXIF is
  lost then). Shows the remaining Free uploads, recognized candidates and a link to the new sighting.
- **No photo** placeholder (car silhouette + caption) wherever a sighting has no photo or the image fails to
  load: cards, timeline, big photo, search dropdown, admin (`fe/src/nophoto.ts`, container queries).
- **Footer** text depends on the UI language (key `footer.message`; empty — no footer; currently only the
  Ukrainian locale has one).
- **Report** button: a modal with a reason, an optional comment → `Complain` → "Thank you".
- **Settings on the logo** (hover/focus; first tap on touch screens): language EN/DE/CH/RU/UA
  (stored in `localStorage`; switching reloads the page; addresses are transliterated for other languages),
  token login / API token balance, and **theme** auto/light/dark (`localStorage`, `data-theme` on `<html>`, set by an inline script in
  `index.html` before load so there is no flash of light background).
- `VITE_INCLUDE_TEST_DATA=true` (set in docker-compose) — the frontend sends `include-test-data`:
  the database currently holds only test data.
- Hot reload in Docker: `fe/` is mounted into the container and Vite watches files by polling
  (`VITE_USE_POLLING`) — on macOS file events from a bind mount are unreliable. `node_modules` come from
  the image; after changing `package.json`: `docker-compose up -d --build fe`.

## Data

The DB schema is goose migrations in `be/migrations` only: files `NNNN_name.sql` (numbered consecutively
from `0001`, sections `-- +goose Up` / `-- +goose Down`). The `migrate` service in docker-compose applies them
(`goose up` on `make etc` / `make run`, then `s3-init`), by hand — `make migrate [CMD=…]`; versions are in the
`goose_db_version` table. The `be` code knows nothing about migrations.
Until the first release the schema is edited in place in `0001_init.sql`; after that — a new migration
(`make migration NAME=…`), applied migrations are never changed.

Tables:
- `plates` — plates: `id uuid` (`gen_random_uuid()`), `plate text UNIQUE` (`А123ВС 777`, `B MW 1234`, `京A·12345`),
  `meta jsonb` (`{"type": "ru"|"eu"|"us"|"ua"|"cn", "region": "D"|"CA"…}`; no `type` — unknown format),
  `is_test_data`. GIN index on `to_tsvector('simple', plate_search_key(plate))` — prefix search with
  `to_tsquery`, no Postgres extensions (no `pg_trgm`).
- `plate_sightings` — sightings: `id uuid`, `plate_id uuid → plates(id)`, `address`, `address_locale`
  (language of the address), `photo_key` / `photo_thumb_key` (S3 object keys of the photo and its thumbnail),
  `created_at` (`timestamptz`), `lat` / `lon` (WGS 84, nullable together), `is_test_data`.
  Indexes: `(created_at DESC, id)` for listing, `(plate_id, created_at DESC, id)` for `Get`.
- `clarifications` — suggested plates for a sighting: `sighting_id`, `plate`, `plate_type`/`plate_region`,
  `status` (`not_accepted` / `accepted`), `created_at`, `is_test_data`.
- `complaints` — photo complaints: `sighting_id`, `reason` (`wrong_plate`, `bad_photo`, `personal_data`,
  `other`), `comment` (≤ 500), `status` (`new` / `resolved`), `created_at`, `is_test_data`.
- `plate_sightings.hidden` — hidden by an admin (`HideSighting`); `uploaded_by → users(id)` and `uploaded_at` —
  who uploaded it via `Ingest` and when (`created_at` is the shot time); NULL for test data.
- `users` (`token_hash` = sha256 of the `cs_…` token, optional unique `email`, `plan` free/pro, `pro_until`) and
  `payments` (`plan`, `amount_cents`, `currency`, `status` pending/succeeded/canceled, `provider` = `mock`).
- `camera_requests` — `lat`/`lon`, `address`, `reason`, `contact`, `status`, `votes`.
- `api_tokens` (`signature_hash`, `requests_total`, `requests_left`, `revoked`, `last_used_at`) and `plate_views`
  (every `Get`: sighting, plate, token, `consumed`, user, `is_admin`, user agent).
- `plate_search_key(text)` — SQL function that folds look-alike characters (see [Search](#search)).

### Backend layers

```
implementation (RPC, validation, mapping to proto)
   └─► usecase (scenarios, transactions: InReadTx / InWriteTx)
          └─► repository (plain SQL; methods take tx db.Executor as the second argument)
                 └─► db (Executor over pgx.Tx: Select/Get/Exec + SelectSqr/GetSqr/ExecSqr; Cluster)
```

- Dependency interfaces are declared by the consumer in its `contracts.go`: `implementation` — usecase,
  `usecase` — `transactor` and `repository`, `db` — `Executor`, `querier`, `Sqlizer`.
- Next to them, `//go:generate minimock …` → mocks in `<package>/mocks/*_mock.go` (`make gen-mocks`);
  tests use the mocks, no hand-written stubs.
- `InReadTx` — read only + REPEATABLE READ: `count` and the page in `Search` come from the same snapshot.
- `models` — `Plate`, `PlateSighting`, `Clarification`, `Complaint`, `SearchOpts`, `SearchPage`, `Market`,
  `ErrNotFound`; `db` tags are for scany.
- `*Sqr` methods take a builder with `ToSql()` (the `squirrel.Sqlizer` contract).
- SQL is also tested against a real database: `go test ./internal/repository/` with `TEST_DATABASE_URL` —
  only on a separate throwaway database with migrations applied (the tests insert rows); without the
  variable these tests are skipped.

### Test data

Created by an ordinary migration `be/migrations/0002_test_data.sql` on `make etc` / `make run`; every row is
marked **`is_test_data = true`**. The backend returns it only with the `include-test-data` header; Down deletes
only test rows (`make migrate CMD=down`) and leaves real ones alone.

The set is generated in SQL (`setseed` — identical on every load): 8 Russian cities, valid letters and region
codes, ~200 RU plates, 600 sightings — a plate usually has several in different places of its city, times
within 180 days, coordinates around the city centre. Plus plates of other markets with addresses in the local
language: Germany (`B MW 1234`, …), USA (`7XYZ123`, `KDT-4419`, …), Ukraine (`АА 1234 ВС`, …), China
(`京A·12345`, …), France/Poland and one plate without a format (`ТАКСИ 01`) for the **Other** tab.
Every test sighting has coordinates (the migration fails otherwise). A few clarifications, complaints and
camera requests are included too, and a test **Pro user** with token `demo-token` (one paid payment). Fixed records for manual checks: `А123ВС 777` — 3 sightings (ids `…0001`, `…0004`, `…0005`),
`М456ОР 178`, `Т789УХ 116`.

**Test photos** `car-1..10.jpg` (1600 px) and `car-N_thumb.jpg` (480 px) are real CC0 / public-domain photos
from Wikimedia Commons (sources and authors — `be/internal/test_utils/s3/cars/CREDITS.md`). Since the plate on

## Dependencies and environment

If your machine has corporate/private registries configured globally (`~/.npmrc`,
`go env -w GOPROXY=...`), they easily leak into lock files. Protection:

| Where | How |
|---|---|
| npm | `fe/.npmrc` → `registry=https://registry.npmjs.org/`; the lock file is built from npmjs |
| Go | `Makefile` and `be/Dockerfile` set `GOPROXY=https://proxy.golang.org,direct`, `GOSUMDB=sum.golang.org` |
| Docker images | Docker Hub (`postgres`, `rustfs/rustfs`, `golang`, `node`, `alpine`, `kukymbr/goose-docker`, `amazon/aws-cli`) |
| CI | the workflow sets the same variables and runs `make check-registries` |
| Local shell | `.env` (below) overrides global variables |

### `.env`

It contains no secrets. Create it in the project root:

```bash
cat > .env <<'EOF'
# Pet project: override global settings — public registries only.
# npm: ignore ~/.npmrc (global registry and scopes)
NPM_CONFIG_USERCONFIG=/dev/null
NPM_CONFIG_REGISTRY=https://registry.npmjs.org/
# Go: public proxy and checksum database
GOPROXY=https://proxy.golang.org,direct
GOSUMDB=sum.golang.org
GOPRIVATE=
GONOPROXY=
GONOSUMDB=
GOFLAGS=
EOF
```

Load it before `npm install` / `go get` in the current shell: `set -a; source .env; set +a`.
`make` commands set these variables themselves. `.env` is in `.gitignore`.

## Access from the local network

Vite listens on all interfaces (`server.host: true`), Docker publishes `7173` on `0.0.0.0`.
Link for others: `http://<your-IP>:7173`.

Port `7173` was chosen instead of the usual `5173` because of a particular machine's firewall rules.
If your firewall allows inbound traffic only on certain ports, change the port in
`fe/vite.config.ts` (`server.port`) and in `docker-compose.yml` (`ports`).
`strictPort: true` keeps Vite from silently jumping to a neighbouring — possibly blocked — port.
Ports `7000` and `5000` on macOS are taken by the AirPlay receiver.

A typical symptom of a blocked port: ping works, but the page does not open for others.

### If others cannot open the page

1. **The server listens on all interfaces:** `lsof -nP -iTCP:7173 -sTCP:LISTEN` → should show `*:7173`.
2. **It answers on the network address:** `curl -I http://<your-IP>:7173/` from your machine.
3. **Packets arrive:** `sudo tcpdump -i en0 -nn 'tcp port 7173'`, then ask someone to open the link.

   | In tcpdump | Meaning |
   |---|---|
   | nothing | the request does not arrive: their VPN/proxy, Wi-Fi client isolation, wrong IP |
   | only `[S]`, no `[S.]` reply | your Mac drops it: firewall (`sudo pfctl -s rules`), EDR, network filter |
   | `[S]` → `[R.]` | nobody listens on the port |
   | full exchange, `[P.]` | the network is fine — look at their browser |

4. **Also check:** they open `http://` (not `https://`); their IP is in the same subnet; the terminal/IDE
   that runs the server outside Docker has "System Settings → Privacy & Security → Local Network" enabled.

The dev server is visible to everyone on the network — do not do this on public Wi-Fi.
Do not disable someone else's (corporate) firewall rules — pick an allowed port instead.

## Account and payments (demo)

There is no login/password: `/signup` (`Register`, optional e-mail) returns a `cs_…` token once (the DB keeps only
its sha256); you log in by pasting it into the **Token** field in the logo settings panel or on `/account`.
After `Me` confirms it, the token is stored in the `cs_token` cookie. The backend reads the cookie or
`Authorization: Bearer <token>`. Plans — `/pricing` (`Plans`: Free / Pro 299 ₽ per 30 days; constants in
`be/internal/usecase/accounts.go`; Free is limited to 5 photo uploads per 24 h, Pro is unlimited — see [Ingest](#ingest-photo-upload-with-ocr)).
Payment — the demo checkout `/pay/mock/<id>` (`CreatePayment` → `ConfirmMockPayment`; no money is charged, Pro is
extended by 30 days from max(now, `pro_until`)); history — `/account` (`ListMyPayments`).
Test Pro user (migration 0002): token `demo-token`, only with the `include-test-data` header:

```sh
curl -s -XPOST localhost:8080/api/carsearch.CarSearchService/Me -H 'include-test-data: true' -b 'cs_token=demo-token' -d '{}'
```
